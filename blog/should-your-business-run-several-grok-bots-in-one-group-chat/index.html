Should Your Business Run Several Grok Bots in One Group Chat?

November 23, 2026 · By David McCormick · 7 min read

Use a group chat when a job has clear stages that different Bots own, and keep a single Bot when one Bot can do the whole job. Grok Bot lets you put two to six Bots in one group chat where they share an outcome and hand work to each other. It works best with one owner per stage, a firm rule about when Bots may message each other, and as few Bots as the job really needs, because every Bot reply counts toward your usage.

What is a Grok Bot group chat?

It is one conversation with two to six Bots in it, built for shared outcomes and visible handoffs. According to the Grok Bot docs on messaging and collaboration, you start one with New chat, Cmd/Ctrl+Shift+N, or New group chat in the command palette, then add the Bots in the To: field. On iPhone or Android it is + and then New Group Chat. You can rename the group and change who is in it later.

Each Bot keeps its own memory and its own skills. The group just gives them one place to talk, so you can see who did what without copying results from one chat to another.

When does a group beat one Bot?

When the work splits into stages with different owners, such as gather, write and check. The docs list good reasons to hand work between Bots: one Bot owns a source system and another owns the deliverable, a specialist should review a draft, a blocker belongs to another role, or a long job should keep moving without you coordinating every step.

People are noticing this on X too. One post from @khuzwayo24 called group chats a feature people sleep on and said one bot doing everything was a mess for them. That matches what we see: a Bot with one clear job is easier to trust and easier to fix.

If a single Bot can finish the task in one pass, a group mostly adds replies. Start with one Bot, and add a second only when you can name the stage it will own.

How do you set up roles so Bots don't step on each other?

Give every stage exactly one owner and say where the work stops. The docs suggest a kickoff that names each Bot and its stage, for example a Researcher that gathers sources and links every claim, a Writer that turns the findings into a draft, and a Reviewer that checks the draft and lists only blocking issues, with a clear "do not publish anything" at the end.

A few habits keep it clean:

  • Use @mentions on purpose. Type @ and pick a Bot when one Bot owns the request. Write normally only when you want the Bots to decide who answers.
  • Reply to the right Bot. Choose Reply on a Bot's message to send your answer to that Bot.
  • Save @everyone for real updates. The docs say to use it sparingly.
  • Avoid parallel handoffs. The docs warn that they create duplicate work and noisy updates.

Can you stop Bots from messaging each other?

Not with a switch, only with instructions. The docs say plainly that there is no switch for this. Bots message each other to hand off work, and they follow what you tell them. Tell the group something like "Don't message other Bots. Ask me first," then ask each Bot to remember it. If one Bot keeps starting new work, open its own chat and ask it to stop.

The same tip has been going around on X. A post from @ura_unico, written in Japanese, recommended writing that ask-me-first rule at the start, since there is no off switch.

Also tell the Bots where to answer. A Bot can message you in its own chat instead of the group. If you want everything in one place, say "Reply here in the group" and ask each Bot to remember that rule for group chats.

What doesn't show up in a group chat?

Approvals, secret and login requests, and email or Slack drafts stay in each Bot's own chat. Files, questions and forms do appear in a group, and your answer goes back to the Bot that asked. But if a Bot is waiting on an approval or a sign-in, you will not see that in the group. Check the Bot's one-to-one chat when work seems stuck.

Two more limits from the docs are worth knowing. Bot-to-group handoff messages are text only, so if one Bot needs to look at an image, the other Bot should send it directly. And you can add a Bot a teammate shared with you, but not alongside Bots that run on your own computer. Group chats also don't have the per-Bot Notifications switch.

How does a group chat affect your usage?

Every Bot reply counts, including replies in the group and messages between Bots. That is straight from the docs, which add that fewer Bots in a group means fewer replies. A group of six Bots that all answer every message can use far more than one Bot doing the same task.

To keep it lean, keep the group small, use @mentions so only the owner answers, and turn off notifications or hide a helper Bot you don't need right now instead of leaving it active. Our earlier post on keeping Grok Bot from running out of usage covers more settings.

How does Spark Media set up Bot teams for a business?

We design the group around the workflow, one Bot per stage, with a person at every decision that matters. As GrokBot and OpenClaw specialists, we usually start with one Bot for front door intake from your website and calls, then add others only when a stage clearly needs its own owner. Common splits are a Bot that runs lead reactivation and follow-up in GoHighLevel, a Bot that watches ad performance, and a Bot that keeps your site content current, with one of them acting as the reviewer.

Every group gets a written kickoff with owners and stopping points, the ask-me-first rule for Bot-to-Bot messages, and approvals for anything a customer sees. Then we trim any Bot that is not pulling its weight.

Frequently asked questions

How many Bots can be in a Grok Bot group chat?

Two to six. The Grok Bot docs say you add two to six Bots in the To: field when you start a new group chat, and membership can be edited later.

Can I stop Bots in a group from messaging each other?

There is no switch for it. The docs suggest telling the Bots in the chat not to message other Bots and to ask you first, then asking each Bot to remember that rule.

Do messages between Bots count toward my Grok Bot usage?

Yes. The docs say every Bot reply counts toward usage, including replies in a group and messages between Bots, so fewer Bots in a group means fewer replies.

Why did an approval request not show up in my group chat?

Approval requests, secret and login requests, and email or Slack drafts do not appear in a group. Look for them in that Bot's own one-to-one chat.

Can I add a teammate's shared Bot to my group?

Yes, a Bot a teammate shared with you can join a group, but not alongside Bots that run on your own computer.
